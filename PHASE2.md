Evidence tags: **[V]** I ran a probe on this machine (scratch files in /tmp only, no repo files touched). **[R]** read in code, not run. **[I]** inference, not run.

### P0 defects found while reading (fix before anything else; none are "features")

1. **Server can be crashed by one request.** `runProcess` in `server/batchRoutes.ts` calls `child.stdin.write(stdin)` with no `'error'` handler. A large stdin to a tool that exits early (`grep -q`, a bad `sed` script) raises an unhandled `EPIPE` and kills the process [V: same pattern on a 5 MB write to `true` killed Node]. In the desktop app the server runs inside Electron's main process (`electron/main.ts: startLocalServer`), so the whole app dies. [R/I for the Electron part]
2. **Desktop app likely loses the canvas on every launch.** `electron/main.ts` starts the server on port 0 (random) and loads `http://127.0.0.1:<port>`; MyGo does the same (`mygo/launcher.cjs`). tldraw persists to IndexedDB (`client/App.tsx: persistenceKey="tldraw-ai-canvas"`), localStorage holds backup settings, and PGlite uses `idb://ai-canvas`. Web storage is keyed by origin including port, so each launch is a new empty origin. [I: standard web-storage rules, not run]
3. **Origin guard lets `Origin: null` through.** `server/index.ts` skips the check when `origin === 'null'` (sandboxed iframes, `data:` pages send exactly that). Hono's `c.req.json()` does not check Content-Type, so a `text/plain` POST is a CORS "simple request" with no preflight. A hostile web page can therefore trigger `/api/tool`, `/api/agent-job`, `/api/sqlite/dump` on a known port (`8790` in dev/`npm start`). Response is unreadable, side effects are not. [R, exploit not run]
4. **Secrets in canvas JSON.** `RawModelNode.apiKey` and `HttpNode.authValue` are node props. They end up in IndexedDB, `/api/backup` snapshots (including S3), `data/history/ops.jsonl`, saved custom nodes, and, via `client/pipeline/assist.ts: nodeSummary` (includes every non-empty string prop ≤ 400 chars), **in the prompt sent to the LLM** by the AI star / fill / compose. [R]
5. **For each swallows failures.** `runLoopBody` returns `null` when the body fails; `ForEachNodeDefinition.execute` does `results.push(value ?? items[i])`, so a failed step emits the unchanged input as if it were a result. [R]
6. **Stop does not stop loops or in-flight work.** `ExecutionGraph.stop()` only sets a flag. `runLoopBody` and `SubgraphNodeDefinition.execute` create their own `ExecutionGraph`s that are not in `executionState`, and the For each `for` loop never checks anything. `/api/generate-text` has no abort signal (only `/api/chat` and `/stream` pass `abortSignal`), so tokens keep being spent. [R]

## 8. Complex-flow features to refuse for now

What the engine is today [R]: one in-memory `ExecutionGraph` pass per Play, executed in the browser against live tldraw shapes; downstream-only run with the last stored results of upstream nodes as inputs; parallel branches; For each is a sequential nested graph with a feedback port (`result`); every node stores its last output in its own props (canvas JSON); `STOP_EXECUTION` means "skip", there is no error value; one `runningGraph` per editor; no job ids, no queue, no run persistence (`nodeRunState` is an in-memory atom).

### ComfyUI-like graph (`comfy_flow`): refuse

| Needs | Engine today | Gap |
|---|---|---|
| Server-side executor on a serialised graph (not tldraw shapes) | Client only; requires `Editor` | Extract engine from shapes, define a graph JSON, move to server (L) |
| Job queue, ids, priorities, progress stream, cancel | None | Queue + WebSocket/SSE + abort plumbing (L) |
| Content-hash cache per node, partial re-run | Implicit only: last result in node props | Hash(inputs+params+node version), invalidation, storage (M–L) |
| Batch semantics (lists of images/latents) | Text lines via For each | New value types, broadcast rules (L) |
| Model loaders, VRAM budget, GPU scheduling | `resolveModel` picks a provider per request; inference is remote HTTP (Ollama etc.) or the browser | A model manager and a GPU worker (L, open-ended) |
| Already decided | `server/config.ts` drops old "ComfyUI, Replicate" providers on load | The owner cut this once |

Honest estimate [I]: 2–3 months for a credible subset (headless engine, queue, cache, output store); GPU/model management is a separate 1–2 months and never really finishes. **Recommendation: refuse.** If ComfyUI itself is wanted, a single "call ComfyUI workflow" node (POST `/prompt`, poll `/history` on `127.0.0.1:8188`) is **M** and reuses the real engine. **DEFER**; not phase 2.

### n8n-like flow settings (`n8n_flow`): refuse

| Needs | Engine today | Gap |
|---|---|---|
| Triggers: schedule, webhook, file watch | Play button only | A headless executor (L) plus server timers (S–M) |
| Webhooks | Server binds `127.0.0.1` and rejects foreign Host/Origin (`server/index.ts`) | Public exposure, auth, replay protection (M–L); conflicts with the local-only design |
| Credentials vault | Keys in `ai-config.json` (0600); node-level secrets in canvas JSON (P0 #4) | Encrypted store (Electron `safeStorage`; MyGo has none), reference-by-name from nodes (M) |
| Retries / backoff | None; each node picks its own timeout | Per-node policy, idempotency guard (S for http/LLM only) |
| Error branches | `STOP_EXECUTION` = skip; errors are strings on the node | An error port, error value type, engine routing (M) |
| Execution log | In-memory `nodeRunState`; `history` is a shape-edit log | Run records on disk, UI (S–M) |

Honest estimate [I]: 2–3 months for the full list (headless engine dominates). **Recommendation: refuse everything except the following minimal pieces:**
1. **Run log (S, keep):** append `{runId, start, nodes:[{id,type,status,ms,message}]}` to `data/runs/runs.jsonl` from `ExecutionGraph` at the end of a run; show the last 20 in the existing history panel. Gives "what happened, when" without a new engine.
2. **Per-node retry (S, DEFER):** only on `http` and LLM nodes (`retries`, fixed delay), after the cancel/timeout work. Not before; it hides errors.
3. **Secrets by reference (M, but already in the P0 list):** this is the only "vault" worth doing.
